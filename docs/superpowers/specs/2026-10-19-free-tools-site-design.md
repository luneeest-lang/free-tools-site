# 무료 도구 웹사이트 설계 (한국어 / English)

- 작성일: 2026-10-19
- 상태: 승인됨

## 1. 목표

검색으로 들어와 바로 쓸 수 있는 무료 온라인 도구 모음을 만든다. 한국어와 영어 사용자를 모두 받는다. 서버 없이 정적 파일로 동작하며, 입력값은 브라우저 밖으로 나가지 않는다.

## 2. 범위

**포함**
- 계산기 4종: 대출 이자, 날짜 차이, BMI, 퇴직금
- 텍스트 도구 4종: 글자수 세기, 대소문자 변환, 줄바꿈·공백 정리, 중복 줄 제거
- 한국어 / 영어 페이지 (각 도구 페이지마다 두 언어 버전)
- 언어 선택기
- 검색 엔진용 메타데이터, 사이트맵, robots.txt

**제외**
- 회원가입, 로그인, 서버 저장
- 광고, 분석 도구 연동 (트래픽이 생긴 뒤 별도 설계)

## 3. 언어 지원

### 3.1 URL 구조

언어는 경로로 구분한다. 검색 엔진이 언어별 페이지를 따로 색인하도록 하기 위해서다.

```
/                          언어 선택 안내 페이지
/ko/                       한국어 홈
/en/                       영어 홈
/ko/loan-calculator/       한국어 대출 이자 계산기
/en/loan-calculator/       영어 대출 이자 계산기
```

루트(`/`)는 브라우저 언어(`navigator.language`)를 보고 `/ko/` 또는 `/en/`으로 안내한다. 검색 엔진이 두 언어 링크를 모두 볼 수 있도록 실제 링크도 함께 둔다. 자동 이동은 `/` 한 곳에서만 일어나며, 도구 페이지에서는 자동 이동하지 않는다.

### 3.2 언어 선택기

- 헤더 오른쪽에 `한국어 / English` 링크를 둔다.
- 링크는 현재 보고 있는 도구의 다른 언어 버전으로 이동한다. 예: `/ko/bmi/` → `/en/bmi/`
- JavaScript 없이 동작하는 일반 링크로 만든다.
- 언어 설정을 따로 저장하지 않는다. URL이 곧 언어 설정이다.

### 3.3 검색 엔진 대응

- 모든 페이지에 `<html lang="ko">` 또는 `<html lang="en">`을 둔다.
- 같은 도구의 두 언어 페이지는 서로를 가리키는 `hreflang` 태그를 둔다.
- `sitemap.xml`에 두 언어 주소를 모두 넣고 `xhtml:link`로 서로 연결한다.

### 3.4 텍스트와 형식

- 페이지 본문, 제목, 설명, 라벨은 언어별로 따로 쓴다. JavaScript로 바꾸지 않고 HTML에 그대로 넣는다. 그래야 검색 엔진이 텍스트를 읽을 수 있다.
- 숫자, 날짜 형식은 `Intl`을 써서 언어에 맞춘다 (`ko-KR`, `en-US`).
- 통화 기호는 언어별 설정으로 둔다. 한국어는 원화(₩), 영어는 달러($)를 기본으로 한다.

### 3.5 번역 범위에 대한 결정 필요

**퇴직금 계산기**는 한국 근로기준법에 기반한 도구다. 영어 페이지에는 "Korean severance pay" 같은 설명을 붙이고, 계산 기준이 한국 제도임을 명확히 적는다. 영어 사용자에게 혼동을 줄 수 있으므로 이 항목은 검토가 필요하다.

## 4. 파일 구조

```
site/
  index.html                언어 선택 안내 (루트)
  ko/
    index.html              한국어 홈
    loan-calculator/index.html
    date-diff/index.html
    bmi/index.html
    severance/index.html
    char-count/index.html
    case-convert/index.html
    line-cleanup/index.html
    dedupe-lines/index.html
  en/
    (같은 구조)
  assets/
    style.css               공통 스타일
    common.js               언어 선택기, 공통 동작
    tools/
      loan-calculator.js    도구별 로직 (화면 연결 포함)
      ...
  sitemap.xml
  robots.txt
content/
  ko/…, en/…                언어별 본문, 제목, 설명 (원본 텍스트)
src/
  logic/                    순수 계산 함수 (DOM을 쓰지 않음)
  test/                     계산 함수 테스트
scripts/
  build.js                  content와 템플릿으로 site/ 생성
```

### 4.1 빌드 스크립트 (결정 필요)

같은 HTML 구조가 도구 8개 x 언어 2개 = 16 페이지에 반복된다. 손으로 16개를 맞추면 헤더, 푸터, 메타 태그가 어긋나기 쉽다.

**제안**: 템플릿과 언어별 텍스트 파일에서 `site/`를 만드는 작은 Node 스크립트(`scripts/build.js`)를 둔다. 외부 패키지는 쓰지 않는다. 배포되는 결과물은 여전히 HTML, CSS, JavaScript만이다.

이는 2절의 "빌드 단계 없음"에 대한 예외다. 이 예외를 승인하는지 확인이 필요하다. 승인하지 않으면 16개 페이지를 직접 관리한다.

## 5. 도구 동작

- 계산 로직은 `src/logic/`의 순수 함수로 둔다. 입력을 받아 결과를 돌려주고 화면을 건드리지 않는다.
- `assets/tools/*.js`는 입력 칸과 결과 칸을 연결하는 얇은 계층이다.
- 입력이 잘못되면 언어에 맞는 안내 문구를 보여준다.
- 대출 이자, 퇴직금 계산은 결과의 계산 방식(월 상환 방식, 근속 기간 계산 등)을 페이지 본문에 짧게 설명한다.

## 6. 검색 최적화 콘텐츠

각 도구 페이지에는 다음을 둔다.

- 고유한 `<title>`과 `<meta name="description">`
- H1 제목 (도구 이름)
- 도구 사용법 설명 2~3문단
- 자주 묻는 질문 3개 안팎

페이지마다 텍스트가 다르도록 쓴다. 같은 문장을 여러 도구에 복사하지 않는다.

## 7. 테스트

- **단위 테스트**: `src/logic/`의 계산 함수에 대해 알려진 입력과 답을 비교한다. 예: 대출 원금, 금리, 기간을 넣었을 때 월 상환액이 맞는지, 날짜 차이가 맞는지, 윤년 처리가 맞는지.
- **페이지 점검 (빌드 후 자동)**: 모든 페이지에 `lang` 속성, `hreflang`, `title`, `description`이 있는지 확인한다.
- **수동 점검**: 모바일과 데스크톱 화면, 언어 선택기 이동, 입력 오류 메시지를 직접 확인한다.

## 8. 배포

GitHub Pages 또는 Cloudflare Pages에 `site/` 폴더를 올린다. 두 서비스 모두 무료이며 정적 파일을 그대로 제공한다.

## 9. 결정 사항

1. **빌드 스크립트 사용**: 승인. `scripts/build.js`를 둔다. (4.1절)
2. **퇴직금 계산기 영어판**: 설명을 붙여 유지한다. 계산 기준이 한국 제도임을 페이지에 명시한다. (3.5절)
3. **Git 저장소**: 초기화하고 설계 문서를 커밋한다.
